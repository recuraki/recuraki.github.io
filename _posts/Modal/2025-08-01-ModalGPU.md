# [GPUアクセラレーション](https://modal.com/docs/guide/gpu)

Modalではfunctionデコレーションに対してgpuを与えるだけで簡単にT4からB200までnのGPUを接続できる。また`:`によりGPU枚数を選択することができ、例えば、`gpu="H100:8"`はH100を８枚 reserveする。また、GPUが確保できない場合もあるため、fallbackできる。`gpu=["H100", "A100-40GB:2"]`などとすることでfallback先を順番に指定できる。

なお、Modalはリソース割り当ての問題でH100がリクエストされた時にH200のインスタンスを渡すことがある。ただしH200はH100の上位互換であるため問題なく利用できる。この自動upgradeを利用しないようにすることもできる。

# [ModalでのCuda利用について](https://modal.com/docs/guide/cuda)

CUDAについて話すときは、CUDAがいくつかのレイヤに分かれていることを注意して語る必要がある。

Lv0: Kernel DriverはGPUと密接したOSのドライバのことであり、このレイヤの挙動をユーザが触ることはない。

Lv1: User mode driverは、Lv0との橋渡しを行うレイヤであり、ユーザ空間で動作するlibcuda.soであったり、`nvidia-smi`のようなコマンドラインプログラムにより構成されている。

Lv2: CUDA Toolkitは、CUDAランタイムAPIを提供し(libcudart.so)ているが、Modalでは(Pythonユーザを主としているので)標準でインストールされてない。しかし、nvrtcのようなこれを使うライブラリはLLMの学習・推論ツールでは頻繁に使われるため、必要に応じてインストールが必要である。

# [Reserving CPU and memory](https://modal.com/docs/guide/resources)

CPUやメモリの予約方法について話そう。Modalの標準のプロセスは`0.125 CPU cores and 128 MiB`という小さなコンテナで起動される。これはもちろん増やすことができて確保すべきメモリ容量を指定することができる。

CPUの確保は`@app.function(cpu=8.0)`などによって行える。メモリの確保は`memory=32768`などによって行える。単位は`MB`であるのでこの例では`32GB`を予約していることになる。なお、これらの上限はそんざいするので多量のリソースを確保しようとするとエラーになる。なお、ストレージ容量はメモリの20倍が確保される。

`_limit`を使うとこれらのcapをかけることができる。メモリの場合はこれを超えるとOOMとしてプロセス自信の実行が終了されることに注意。
